### Q1: What is JDBC and what is its role in this project?
**Answer:**
JDBC stands for **Java Database Connectivity**. It is a standard Java API (Application Programming Interface) provided in the `java.sql` package that enables Java programs to interact with relational databases. In this project, JDBC acts as the communication bridge between our Java console application and the MySQL database to execute SQL operations like inserting, querying, updating, and deleting lost/found records.

---

### Q2: What are the main steps required to connect a Java application to a database via JDBC?
**Answer:**
There are 5 key steps:
1. **Load/Register the JDBC Driver:** `Class.forName("com.mysql.cj.jdbc.Driver");`
2. **Establish the Connection:** `Connection conn = DriverManager.getConnection(url, user, password);`
3. **Create a Statement / PreparedStatement:** `PreparedStatement ps = conn.prepareStatement(sql);`
4. **Execute the Query:** `ps.executeUpdate()` for INSERT/UPDATE/DELETE or `ps.executeQuery()` for SELECT.
5. **Process Results & Close Resources:** Iterate over `ResultSet` and close connections (automatically handled using try-with-resources).

---

### Q3: What is the difference between Statement and PreparedStatement?
**Answer:**
| Feature | Statement | PreparedStatement |
|---|---|---|
| **Compilation** | Compiled every time it is executed. | Pre-compiled once by the database engine. |
| **Performance** | Slower when executed repeatedly. | Faster because the query plan is cached. |
| **Parameters** | Cannot use placeholders (`?`). Values must be concatenated. | Uses placeholders (`?`) with typed setter methods (`setString`, `setInt`). |
| **Security** | Vulnerable to **SQL Injection** attacks. | **Immune to SQL Injection** because parameter values are treated as data, not executable code. |

### Q4: What is SQL Injection, and how did you prevent it in this project?
**Answer:**
SQL Injection is a code injection technique where malicious users enter SQL fragments into input fields to alter the logic of database queries. We prevented SQL Injection by **exclusively using `PreparedStatement` with parameterized placeholders (`?`)** throughout `ItemDAO.java`. Input values are safely bound via `ps.setString()`, `ps.setInt()`, and `ps.setDate()`, preventing input from being interpreted as SQL commands.

### Q5: What is a ResultSet, and how does it work?
**Answer:**
A `ResultSet` is an interface in `java.sql` that represents a tabular data stream generated by executing a `SELECT` SQL query. It maintains an internal cursor pointing just before the first row of data. When we call `rs.next()`, the cursor moves to the next row (returning `true` if a row exists, or `false` when exhausted). We retrieve column values using getter methods like `rs.getInt("id")` and `rs.getString("item_name")`.

### Q6: What is the DAO (Data Access Object) design pattern, and why did you use it?
**Answer:**
The **DAO pattern** isolates the application/business logic from the persistence (database) logic. 
- In our project, `ItemDAO.java` contains all database queries (`INSERT`, `SELECT`, `UPDATE`, `DELETE`).
- `Main.java` only deals with user interactions and calls methods on `ItemDAO`.
- This ensures clean separation of concerns, improves code reusability, and makes maintenance much simpler.

### Q7: What is try-with-resources in Java, and why is it important in JDBC?
**Answer:**
Introduced in Java 7, **try-with-resources** is an automatic resource management feature for objects implementing `java.lang.AutoCloseable`. 
In JDBC, `Connection`, `PreparedStatement`, and `ResultSet` all implement `AutoCloseable`. Placing them inside the parentheses of a `try` block ensures they are automatically closed when execution leaves the block, even if an exception occurs. This prevents database connection leaks and memory exhaustion without requiring verbose `finally` blocks.

### Q8: What is the purpose of `Class.forName("com.mysql.cj.jdbc.Driver")`?
**Answer:**
`Class.forName()` dynamically loads the MySQL JDBC driver class into memory at runtime. During class loading, the driver's static initializer runs and automatically registers the driver with the `DriverManager`. Although JDBC 4.0+ supports auto-registration via SPI, explicitly loading the driver ensures compatibility across all execution environments.

### Q9: What is the difference between `ps.executeUpdate()` and `ps.executeQuery()`?
**Answer:**
- `ps.executeQuery()`: Used for SQL queries that retrieve data (such as `SELECT`). It returns a `ResultSet` object.
- `ps.executeUpdate()`: Used for Data Manipulation Language (DML) statements (such as `INSERT`, `UPDATE`, `DELETE`). It returns an `int` representing the number of rows affected by the query.

### Q10: What is an `SQLException`, and how is it handled in your application?
**Answer:**
`SQLException` is a checked exception in Java that indicates a database access error or invalid SQL execution. In our application, every JDBC call inside `ItemDAO.java` and `DBConnection.java` is wrapped in a `try-catch` block catching `SQLException`. Instead of letting the application crash, it prints an informative error message and safely returns fallback values (e.g., `false` or an empty list).

### Q11: What is a POJO and which class represents it in your project?
**Answer:**
POJO stands for **Plain Old Java Object**. It is a simple Java class without any special framework bindings, containing private fields, constructors, getters, and setters. In our project, `Item.java` is a POJO / Model class that encapsulates the attributes of a lost or found item (`id`, `itemName`, `category`, `description`, `location`, `reportType`, `reportedBy`, `contactNumber`, `reportedDate`, `status`).

### Q12: How did you validate user input to prevent runtime crashes?
**Answer:**
1. **Empty Strings:** The helper method `readNonEmptyString()` repeatedly prompts the user until a non-empty name is entered.
2. **Numeric Validation:** The helper method `readInt()` catches `NumberFormatException` when a user enters non-numeric text for menu options or IDs, asking for a valid number without crashing.
3. **Date Validation:** `readDateInput()` parses input with `LocalDate.parse()` and falls back to today's date if the user presses Enter.
4. **ID Existence Check:** Before updating or deleting, the application checks if the item exists (`getItemById`) and shows an informative message if not found.

### Q13: What is the role of the `AUTO_INCREMENT` and `PRIMARY KEY` in the MySQL table?
**Answer:**
- `PRIMARY KEY`: Uniquely identifies each record in the `items` table, ensuring no duplicate rows exist and preventing `NULL` values.
- `AUTO_INCREMENT`: Automatically assigns an incremental integer value (1, 2, 3...) to the `id` column whenever a new record is inserted, removing the need for manual ID generation.

### Q14: What is the difference between `java.util.Date` and `java.sql.Date`?
**Answer:**
- `java.util.Date` represents both date and time (hours, minutes, seconds, milliseconds).
- `java.sql.Date` is a thin wrapper around milliseconds that corresponds directly to the SQL `DATE` data type, storing only the year, month, and day without time components. We use `java.sql.Date` in JDBC for compatibility with MySQL's `DATE` column.

### Q15: Why did you use `PreparedStatement` with `LIKE` for name search?
**Answer:**
In `getItemsByName(String name)`, we wrote:
```sql
SELECT * FROM items WHERE LOWER(item_name) LIKE LOWER(?) ORDER BY id ASC
```
We bind `"% " + name.trim() + "%"` to the parameter. This enables case-insensitive partial keyword search (e.g., searching for "bottle" will match "Water Bottle" or "Milton Bottle") without risking SQL injection.

### Q16: What happens if MySQL Server is stopped while running the application?
**Answer:**
If MySQL Server is stopped:
1. `DriverManager.getConnection()` throws an `SQLException` (such as `Communications link failure`).
2. The `try-catch` blocks in our code catch this exception and display a clear troubleshooting guide instructing the user to start their MySQL service and check port 3306.
3. The application does not terminate abruptly; the user can return to the menu or exit cleanly.

### Q17: What are the ACID properties in database management?
**Answer:**
ACID represents the four essential properties of database transactions:
- **Atomicity:** All operations in a transaction succeed, or none do ("all or nothing").
- **Consistency:** The database transitions from one valid state to another valid state.
- **Isolation:** Concurrent transactions execute without interfering with one another.
- **Durability:** Once committed, data changes survive system failures.

### Q18: What is the MySQL connection URL format used in `DBConnection.java`?
**Answer:**
```
jdbc:mysql://localhost:3306/campus_lost_found?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
```
- `jdbc:mysql://` : Protocol and sub-protocol indicating JDBC and MySQL driver.
- `localhost` : Hostname where MySQL Server is running.
- `3306` : Default TCP port of MySQL.
- `campus_lost_found` : Name of the target database.
- Query parameters configure SSL disabling for local dev, public key retrieval for MySQL 8+, and UTC timezone alignment.

### Q19: How did you implement the "Mark Item as Returned" feature?
**Answer:**
In `ItemDAO.java`, we implemented `updateItemStatus(int id, String newStatus)`. When the user chooses Option 9 in `Main.java`:
1. It retrieves the item by ID and displays its current status.
2. If already `RETURNED`, it notifies the user.
3. Otherwise, it asks for confirmation (Y/N) and updates the status column in MySQL to `"RETURNED"`.
